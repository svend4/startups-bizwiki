# Точность признаков выгрузки

Дата: 10.11.2026 · Данные: выпуск «Ask HN: Who is hiring? (November 2026)», 221 доступный пост.

## Зачем

Выгрузка `tools/hn_hiring_export.py` отмечает признаки регулярными выражениями: удалённый формат, офис, гибрид, зарплату, упоминание ИИ, YC, e-mail, локацию, резюме-пост, технологии и роли. Эти флаги дают все цифры в `docs/analiz-idei.md`, поэтому их точность нужно было измерить, а не предполагать.

## Как измерено

1. **Выборки.** Из постов, доступных для выгрузки, случайно выбраны два непересекающихся набора по 30 постов: выборка разработки (семя 42) и выборка проверки holdout (семя 43). ID лежат в `tools/eval/manifest.json`. Тексты постов в репозиторий не включены: это пользовательский контент.
2. **Эталон.** Каждый пост независимо размечают три оценщика, разные языковые модели. Оценщики видят только текст поста и определения признаков; регулярные выражения и CSV им не показываются. Эталон признака — большинство голосов. Тег технологии или роли входит в эталон, если его выбрали два оценщика из трёх.
3. **Сравнение.** Точность, полнота и число ошибок по каждому признаку считает `tools/eval/score.py` из эталона `tools/eval/gold.json` (пояснения оценщиков в файл не включены).
4. **Настройка и проверка.** Правила версии 2 подбирались только по выборке разработки. Выборка holdout не использовалась ни для одной настройки, включая размер окна для ролей. Поэтому её результат — честная оценка на новых постах.

## Ограничения

- **Мало постов.** В каждой выборке 30 постов. Признаки с одним-двумя положительными случаями (резюме, YC) по ним не оцениваются строго; цифры — ориентир.
- **Эталон — не человек.** Это большинство голосов трёх языковых моделей. Их ошибки могут совпадать, поэтому результат — проверка согласованности, а не истина.
- **Офис без слова «office».** Если пост просто называет город («Tokyo, Japan») без слов onsite, office или in person, признак не ставится, хотя оценщики иногда считали такую работу очной. Это ограничение метода.
- **Широкий признак ИИ.** Любое упоминание ИИ в тексте засчитывается; эталон требует, чтобы ИИ был частью продукта или работы.
- **Роли — самый слабый признак** (см. результаты holdout).

## Что это значит для цифр

- **Удалённый формат** (57% постов в ноябре): точность и полнота 1.00. Цифра надёжна.
- **Зарплата.** Версия 1 давала ложные суммы: выручку продукта («$10k+»), бонусы, слово «compensation» без цифр. Версия 2 на обеих выборках почти не ошибается (точность 1.00, полнота 0.88–1.00). Поэтому доля постов с суммой в ноябре — 28%, а не 41%, как давала версия 1.
- **Офис и гибрид.** Полнота 0.69–0.82 для офиса: цифра занижена, реальная доля очных вакансий выше названной. По гибриду на holdout точность 1.00, полнота 0.83: часть гибридных постов не ловится.
- **ИИ.** Точность 0.91–1.00, полнота 0.95. Доля 60% ориентировочная: признак включает упоминания ИИ без роли.
- **Технологии.** Точность 0.95–0.99, полнота 0.93–0.98. Цифры по технологиям можно использовать с оговоркой о пропусках.
- **Роли.** Точность 0.81–0.83, полнота 0.57–0.75. Распределение ролей занижено: реальных backend- или ML-вакансий больше, чем названо. Относительные выводы («роли продаж и поддержки заметны») опираются на эти цифры осторожно.
- **E-mail и резюме-пост.** Версия 2 находит и обфусцированные адреса вида «name [at] mail», и посты самих соискателей; полнота e-mail на holdout 0.88 — небольшая недооценка.

## Воспроизведение

```bash
python3 tools/eval/score.py --csv data/hn-hiring-2026-11.csv --set baseline
python3 tools/eval/score.py --csv data/hn-hiring-2026-11.csv --set holdout
```

Команда печатает таблицы выше из текущего CSV. Выгрузка CSV: `python3 tools/hn_hiring_export.py --story 50338728 --out data/hn-hiring-2026-11.csv --prev data/hn-hiring-2026-10.csv`.

## Что изменилось в версии 2

- Зарплата: сумма засчитывается, только если рядом нет слов про выручку, пользователей, бонус, цену, финансирование; голые слова «salary», «compensation», «base» больше не считаются суммой.
- Гибрид: формулировки «N days in office», «come in office N days», «in-office N».
- Роли: совпадение засчитывается только рядом (до 80 символов в той же строке) со словом из названия должности (engineer, designer, manager и др.). Это убрало ложные роли из описания продукта. Регистр исправлен для «Data Science» и «Embedded Software».
- Технологии: строчные «python», «react.js», «postgres» теперь ловятся; «Go» в перечислении языков; «crypto wallet» не считается стеком.
- E-mail: обфусцированные адреса; резюме-посты по фразам «willing to relocate», «available for hire», «Location:» в начале; YC по слову «YC».
